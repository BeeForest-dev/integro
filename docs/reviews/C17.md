# C17 — core.crypto

## Contract
```
Purpose:    encrypt/decrypt connection secrets at rest.
In -> Out:  ciphertext token / plaintext secret.
Errors:     wrong key -> typed error, never returns partial plaintext;
            empty input -> empty output.
Side fx:    none. Key from env (Fernet).
Deps:       cryptography.
```

## Delivery note (written by the implementer)
_Exactly 5 points._

1. What it does: `backend/app/core/crypto.py` provides `encrypt(plaintext, secret) -> str` and `decrypt(ciphertext, secret) -> str` built on Fernet, with `CryptoError` as the single decryption-failure type; empty input maps to empty output in both directions (short-circuit before Fernet).
2. Why it is built this way: the Fernet key is DERIVED from `Settings.SECRET_KEY` via HKDF-SHA256 (length 32, info `b"integro-connection-secrets-v1"`, no salt) and urlsafe-base64 encoded — one env var serves both token signing (C14) and at-rest encryption, separated by key derivation; derivation runs per call (cheap, stateless, no module-level cache); there is no key versioning — a single derived key, rotation is a future ops concern (documented).
3. How it is structured internally: `_derive_key` (HKDF + urlsafe-b64), `encrypt`, `decrypt`, `CryptoError` — ~60 lines, no state. Decrypt catches `(InvalidToken, ValueError, UnicodeEncodeError)` and raises `CryptoError("decryption failed")`: in cryptography 50 `InvalidToken` is NOT a `ValueError` subclass (mutation-proven), and malformed base64 raises `binascii.Error`/`ValueError`, non-ASCII input raises `UnicodeEncodeError` — all converge on the one typed error, never partial plaintext, never a hint about which key was tried.
4. Where the traps / failure modes are: Fernet expects a urlsafe-base64 key — passing the raw 32 HKDF bytes makes the `Fernet` constructor itself raise `ValueError` (caught in development); the ambiguous-character lint (RUF001) rejects Cyrillic letters that look like Latin ones even inside test fixtures (replaced with CJK text); empty-string handling must short-circuit BEFORE Fernet because encrypting "" would produce a valid non-empty token and break the contract's "empty -> empty".
5. How to verify it: no database needed: `ruff check .` clean, `mypy app --warn-unused-ignores` clean (36 files), `pytest` -> **119 passed** (109 previous + 10 crypto tests: roundtrip ascii/unicode/CJK parametrized, empty -> empty both ways, wrong secret -> CryptoError (not InvalidToken), tampered ciphertext -> CryptoError, garbage/non-ASCII ciphertext -> CryptoError, randomized IV, derived key deterministic and != raw secret, truncated token -> CryptoError). Full suite (incl. PG-backed) against compose postgres — green. Mutation self-checks (both required): empty short-circuit removed -> empty test FAILS; `InvalidToken` dropped from the except clause -> wrong-key test FAILS (raw InvalidToken escapes); restored -> suite green.
