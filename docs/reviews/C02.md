# C02 — core.logging

## Contract
```
Purpose:    configure structured JSON logging with request/correlation id.
In -> Out:  configured stdlib logger + helper to bind correlation id.
Errors:     never raises; falls back to plain logging if setup fails.
Side fx:    writes to stdout.
Deps:       structlog, stdlib logging.
```

## Delivery note (written by the implementer)
_Exactly 5 points._

1. What it does: `backend/app/core/logging.py` provides `setup_logging()` — configures structlog to render every log record as one JSON object on stdout and returns the configured stdlib root logger — and `bind_correlation_id()` — a helper that attaches the current request/correlation id to every log record in the context.
2. Why it is built this way: structlog's contextvars processors (`merge_contextvars` + `bind_contextvars`) give per-request correlation-id binding without passing loggers around; rendering through the stdlib bridge (`LoggerFactory` + `basicConfig`) keeps one stdout stream. The whole setup is wrapped in `try/except` so a structlog failure degrades to plain stdlib logging instead of crashing the app, as the contract requires.
3. How it is structured internally: two public functions in `app/core.logging`, no module-level side effects (nothing runs at import); processors: `merge_contextvars` → `add_log_level` → `TimeStamper(iso, utc)` → `format_exc_info` → `JSONRenderer`.
4. Where the traps / failure modes are: `cache_logger_on_first_use=True` means the processor chain is frozen per logger — tests must call `structlog.reset_defaults()`; context vars leak across tests unless `clear_contextvars()` runs in a fixture; `basicConfig(force=True)` reconfigures the root logger on every call so repeated setup in tests stays deterministic; the fallback path swallows any structlog exception by design, so a broken renderer must be caught by the fallback test, not by silence.
5. How to verify it: `cd backend && python -m pytest tests -v` — 11 tests pass (7 for C01 + 4 for C02: stdlib logger returned, JSON on stdout, correlation id present in records, structlog failure -> plain logging fallback without raising).
