# C07 — infra.docker

## Contract
```
Purpose:    multi-stage Dockerfile + compose for api, worker, beat, postgres, redis,
            mock-crm, mailpit.
In -> Out:  `docker compose up` -> 7 healthy services within 60 s.
Errors:     image build fails -> build log shows the failing step.
Side fx:    creates volumes for postgres data.
Deps:       docker only (no python deps added).
```

## Delivery note (written by the implementer)
_Exactly 5 points._

1. What it does: `backend/app/workers/` adds a real Celery app (`celery_app.py`: `Celery("integro")`, broker = `REDIS_URL` db 0, result backend = тот же URL с заменённым путём на db 1, без новых полей Settings) и задачу `ping() -> "pong"` (`tasks.py`, без sleep-заглушек). `infra/Dockerfile` — multi-stage `python:3.13-slim` образ (venv в /opt/venv, non-root uid 1000, CMD uvicorn) на три роли; `infra/mock-crm/` — минимальный FastAPI (GET /health, POST /leads -> 201 эхо+id, in-memory). Корневой `compose.yaml` поднимает ровно 7 сервисов без .env и внешних ключей.
2. Why it is built this way: три роли (api/worker/beat) делят один образ и тег `integro-backend` (image+build на каждой — compose не пытается пуллить); broker и result backend из одного `REDIS_URL` — замена последнего сегмента пути через `urllib.parse`, никаких новых настроек; healthcheck'и без curl/wget в образе приложения — `python -c urllib` (api, mock-crm), `redis-cli ping`, `pg_isready`, busybox `wget` у mailpit (тег `axllent/mailpit:v1.33.0`, `/livez` проверен фактом), worker — `inspect ping | grep -q pong`, beat — pidfile + `kill -0`.
3. How it is structured internally: `celery_app.py` читает `REDIS_URL` из окружения при импорте (без подключения), задачи регистрируются через `include=["app.workers.tasks"]` — без этого воркер стартует с пустым реестром (поймано живым стендом); `main.py` mock-crm хранит лиды в памяти процесса; compose: `depends_on` с `service_healthy` для postgres/redis, секрет `SECRET_KEY: ${SECRET_KEY:-local-demo-only}` — демо-заглушка, комментарием помечено что не секрет.
4. Where the traps / failure modes are: celery beat по умолчанию пишет `celerybeat-schedule` в WORKDIR, который принадлежит root (COPY) — под uid 1000 PermissionError; исправлено флагом `-s /tmp/celerybeat-schedule` (не менять USER на root); worker-healthcheck честно пуст: без воркера `inspect ping` выдаёт «No nodes replied» -> exit 1 (проверено остановкой воркера); beat-healthcheck без pidfile -> exit 1 (проверено перемещением pidfile); uvicorn-стенд гасился по PID, не по маске имени (урок C06). `py.typed` у celery НЕТ (проверено) — ровно один `# type: ignore[import-untyped]` на строке импорта.
5. How to verify it: чистое venv по `backend/requirements.txt`: `ruff check .` clean, `mypy app` clean (15 файлов), `pytest -q` -> 38 passed (37 + test_ping_returns_pong). Живой стенд: `docker compose build` exit 0; `up -d --wait --wait-timeout 60` exit 0; `docker compose ps` -> 7/7 healthy; `/health` 200 `{"status":"ok"}`, `/ready` 200 `{"db":true,"redis":true}`, `/metrics` отдаёт `# HELP`/`# TYPE`; сквозная задача `ping.delay().get(timeout=10)` -> `pong`; `down -v` -> exit 0, контейнеров и volume integro не осталось. Скан секретов: gmail-адресов в репозитории нет; слово spidoznye встречается только в до-C07 файлах (AGENTS.md — документация локального имени папки по собственному правилу проекта; docs/CONVERSATION.md — исторический лог); C07-файлы чистые; `docker compose config` содержит только демо-значения (integro/integro, local-demo-only).

### Required changes
1. English only (standing repo rule). Translate the three comments in `compose.yaml` and rewrite this delivery note in English. While rewriting, refer to "the local working folder" instead of spelling its name.
2. `backend/app/workers/celery_app.py:14` — drop the hardcoded fallback and read `os.environ["REDIS_URL"]`, so a missing value fails at startup instead of silently pointing at localhost. Keep the suite runnable with no external services by setting `REDIS_URL` before the import in `tests/workers/test_tasks.py` (e.g. `os.environ.setdefault(...)` at module top).
3. `backend/tests/workers/test_tasks.py` — add one assertion that the task module is in the app's include list, because that line is what prevents an empty worker registry:
   `assert "app.workers.tasks" in celery_app.app.conf.include`
   The live e2e already proves the behaviour; this is the CI guard.

### Non-blocking notes
1. `worker` depends on `api: service_started` and `beat` depends on `worker: service_started`, but neither needs the other. The ordering is false and makes the graph misleading; drop both edges and keep only the `postgres`/`redis` dependencies that matter.
2. `infra/mock-crm/Dockerfile` runs as root while the main image runs as uid 1000. It is a stub, but the asymmetry is unnecessary.
3. The image is built three times (once per role) because `build:` is repeated under `api`, `worker` and `beat`. A shared `x-backend` anchor would build it once and keep the three roles in sync.
4. `_result_backend_url` replaces only the URL path; a query string or `rediss://` passes through untouched. Correct for the compose URL; a one-line unit test would pin the db-0 -> db-1 mapping.
