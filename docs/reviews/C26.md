# C26 — connectors.triggers.imap

## Contract
```
Purpose:    poll (or IDLE on) a mailbox and normalise new messages into events.
In -> Out:  Event per new message; cursor per mailbox.
Errors:     IMAP auth failure -> connection marked `auth_failed`, no retry storm;
            network timeout -> backoff and retry; broken connection -> reconnect once, then give up.
Side fx:    reads the mailbox only. Cursor persisted.
Deps:       imaplib (stdlib), ssl.
```

## Delivery note (written by the implementer)
_Exactly 5 points._

1. What it does: `app/services/imap.py` (stdlib only, synchronous) fetches messages newer than a UID cursor via `fetch_new_messages(host, port, username, password, folder, last_uid) -> (new_last_uid, messages)`, normalizing each to `{uid, message_id, from, subject, date, body_text}` (first text/plain part, truncated at 20000 chars). Typed errors: `ImapAuthError` (LOGIN rejected), `ImapTimeoutError`, `ImapConnectionError` — connection breaks are retried exactly ONCE inside the service, then the error propagates. `app/workers/mail_poller.py` runs on beat (`poll-mailboxes`, every 60 s — the tick IS the backoff): each ACTIVE `imap_mailbox` connection due per `config.poll_every_seconds` (default 300, cursor `last_poll_at`) is polled read-only; auth failure persists `status="auth_failed"` (new value on the plain String column — model docstring updated, no schema change) so later ticks skip it; timeout logs `imap_poll_timeout` and leaves the status alone; a break after the service's single reconnect logs `imap_poll_failed`. New messages become events (`imap.message`, idempotency key `imap:{connection_id}:{uid}`), the cursor `{"last_uid", "last_poll_at"}` is persisted in `connection.config` with the events, and each created event is enqueued through the spy seam. Config validation (C18 create): `imap_mailbox` requires `config.host`/`config.username` (str) and `config.port` (int when present) — ValueError naming the field.
2. Why it is built this way: polling (not IDLE) is the reviewer's decision — a long-lived IDLE connection does not fit celery tasks, and the beat tick is the retry/backoff mechanism; `readonly=True` SELECT (EXAMINE) keeps the poller read-only by construction; the timeout is a module constant (`IMAP_TIMEOUT_SECONDS`, shrinkable in tests) applied at socket creation; exactly-once comes from the C22 unique index with the UID in the key.
3. How it is structured internally: pure-sync client in `services/imap.py` (connect/login/select/search/fetch/normalize, reconnect-once wrapper); the poller task mirrors C24 (`shared_task` around an async core tests drive directly; `asyncio.to_thread` bridges the sync client); the enqueue seam is lazy like C22/C25; `celery_app.py` gains the mail_poller module in `include` plus the `poll-mailboxes` beat entry (the third documented C07 touch).
4. Where the traps / failure modes are: **imaplib `select(readonly=True)` sends EXAMINE, not SELECT** — the fake server (and any future mocks) must handle both; **RFC822 literals close with `)` immediately after the raw bytes** — a stray CRLF between them makes imaplib raise `abort: unexpected response: b')'`; the C18 round-trip test's imap fixture predated the config validation — its config gained `"username": "user"` (consequence of the sanctioned 5th touch, documented here); my own seed helper initially returned without committing (a flushed-but-uncommitted insert rolls back with the session) — caught by the first test run; `socket.timeout` IS `TimeoutError` (UP041) — one catch covers both.
5. How to verify it: `docker compose up -d postgres`, `DATABASE_URL=postgresql+asyncpg://integro:integro@127.0.0.1:5432/integro`, from `backend/`: `ruff check .` clean, `mypy app --warn-unused-ignores` clean (52 files), `pytest` -> **240 passed** on a freshly recreated database (231 previous + 9 poller tests: happy path with two fully-normalized events + cursor, second poll stores nothing, new uid 103 later yields one event, rejected login persists `auth_failed` with zero events and zero extra logins on the next tick, hanging server -> `imap_poll_timeout` with status still active, mid-session break -> exactly ONE reconnect then `imap_poll_failed` with status active, due-gating never contacts the server, config validation naming each field, body truncated at 20000 chars). Mutation self-checks (both required): `auth_failed` marking removed -> the auth test FAILS; uid dropped from the idempotency key -> the third-poll test FAILS; restored -> suite green.
