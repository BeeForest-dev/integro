# C04 — db.engine

## Contract
```
Purpose:    async SQLAlchemy engine + session factory.
In -> Out:  AsyncSession via dependency injection.
Errors:     DB unreachable -> connection error surfaces as 503, not 500.
Side fx:    opens a pool to PostgreSQL.
Deps:       sqlalchemy[asyncio], asyncpg.
```

## Delivery note (written by the implementer)
_Exactly 5 points._

1. What it does: `backend/app/db/engine.py` provides an async SQLAlchemy engine + session factory for PostgreSQL and `get_session()` — a FastAPI dependency that yields an `AsyncSession` with a verified live connection.
2. Why it is built this way: the module-level engine is initialised explicitly via `init_engine(database_url)` (called from app lifespan later) instead of being created at import — so importing the module has no side effects and tests fully control the DSN; `DatabaseUnavailableError` subclasses C03's `AppError` with `status_code = 503`, so the failure surfaces as 503 through the existing problem-details handlers, never as a 500.
3. How it is structured internally: `create_engine` / `create_session_factory` (pure factories), `init_engine` / `dispose_engine` (module-level lifecycle), `get_session` (async generator dependency), `DatabaseUnavailableError`. `get_session` runs a `SELECT 1` probe before yielding; only after a working connection is confirmed does the endpoint get the session.
4. Where the traps / failure modes are: SQLAlchemy does **not** wrap pre-connection failures — a refused TCP connect escapes as raw `ConnectionRefusedError` (OSError), not `OperationalError`, so the probe catches broadly by design; the probe is a single fixed `SELECT 1`, so any failure there means "no usable connection" = the contract's error case; `asyncio.run`-based tests create/close the engine inside one loop each time to avoid cross-loop pool warnings.
5. How to verify it: `cd backend && python -m pytest tests -v` — 21 tests pass (7 C01 + 4 C02 + 4 C03 + 6 C04: factory yields AsyncSession, unreachable DB -> `DatabaseUnavailableError` with status 503, full HTTP 503 problem-details through FastAPI + C03 handlers, dependency-before-init -> RuntimeError).
