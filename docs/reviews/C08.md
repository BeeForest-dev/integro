# C08 — ci.github-actions

## Contract
```
Purpose:    CI pipeline: ruff -> mypy -> pytest -> docker build.
In -> Out:  green/red badge + PR status check.
Errors:     test failure -> step fails with the failing test name in the log.
Side fx:    uses postgres + redis service containers for integration tests.
Deps:       github actions only.
```

## Delivery note (written by the implementer)
_Exactly 5 points._

1. What it does: `.github/workflows/ci.yml` runs on every push to `master` and every pull request. Job `checks` (ubuntu-latest, Python 3.13 with pip cache) installs `backend/requirements.txt`, then runs `ruff check .`, `mypy app --warn-unused-ignores` and `pytest` from `backend/`, against health-checked `postgres:16` and `redis:7` service containers (`DATABASE_URL`/`REDIS_URL` point at localhost). Job `docker` runs `docker compose build` for all services.
2. Why it is built this way: the pipeline reuses the exact gate commands from the Definition of Done (`ruff` / `mypy app --warn-unused-ignores` / `pytest`) so CI can never drift from what the reviewer runs locally; service containers mirror the C07 compose stack so integration tests that need real PostgreSQL/Redis (added from M1 on) work unchanged; `--warn-unused-ignores` is a one-word guard against stale `type: ignore` comments accumulating (locally verified green before pushing).
3. How it is structured internally: two independent jobs (`checks`, `docker`) so a lint failure and an image failure surface separately; pip caching keyed on `backend/requirements.txt`; no secrets, no environment files — the single placeholder is `SECRET_KEY: ci-not-a-secret`, commented as not a secret.
4. Where the traps / failure modes are: `working-directory: backend` must be set per step (a repo-root `ruff check .` would lint nothing and exit 0 — a silent false green); the postgres service needs its healthcheck (`pg_isready`) or pytest could start before the DB accepts connections; `pull_request` trigger must stay untargeted so PRs from any branch are checked; no README badge — deliberately deferred to M6 per the contract note.
5. How to verify it: local dry-run of the exact commands (`mypy app --warn-unused-ignores` -> exit 0, `ruff check .` clean, 39 passed), then the real proof — commit `480ab60` pushed to `master` triggered run #1: **conclusion `success`**, both jobs green in 55 s (checks: Initialize containers -> Ruff -> Mypy -> Pytest all `success`; docker: `docker compose build` `success`). Run: https://github.com/BeeForest-dev/integro/actions/runs/41442602755
